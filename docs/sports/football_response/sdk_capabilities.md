# Football SDK Capabilities

Verified against the live NFL response docs and SDK chaining notes on
2026-05-09.

This file defines football-focused SDK methods by user intent. The public SDK
surface should accept names, dates, seasons, weeks, or known IDs, then resolve
ESPN IDs and domain-specific endpoints internally.

Raw domain clients can still exist for advanced users, but the primary SDK
should return normalized football data.

| Capability | Input | Output | How we get there |
| --- | --- | --- | --- |
| Search players | `query`, optional `league`, optional `team` | Matching players with `athleteId`, `uid`, `guid`, display name, league/team hints, position when available | Call Search v2 with `query`; filter `results[].type == "player"`; parse numeric `athleteId` from `results[].contents[].uid` using `~a:(\d+)`; optionally enrich with common-v3 athlete or team roster. |
| Resolve player ID | `playerName`, optional `league`, optional `team` | Canonical `athleteId`, `uid`, `guid`, display name | Search v2 by name; use player hits; parse `athleteId` from `uid`; use `guid` from `contents[].id` only as metadata; optionally disambiguate by league/team. |
| Get player profile | `athleteId` or `playerName`, optional `league` | Bio/profile fields: name, team, position, jersey, height, weight, age, experience, links, team history where available | If name is provided, resolve player ID through Search v2; call common-v3 athlete page and/or common-v3 athlete `overview`/`bio`; use core-v2/core-v3 athlete detail only when core refs or graph identity are needed. |
| Get player season stats | `athleteId` or `playerName`, optional `season`, optional `league` | Passing/rushing/receiving/defense/kicking stat tables with labels and categories | Resolve `athleteId` if needed; call common-v3 `/athletes/{id}/stats`; optionally fall back to core-v2 `/athletes/{id}/statistics` when a core `splits` shape is requested. |
| Get player game log | `athleteId` or `playerName`, optional `season`, optional `league` | Game-by-game rows with event IDs, dates, opponents, results, and stat columns | Resolve `athleteId` if needed; call common-v3 `/athletes/{id}/gamelog`; normalize `events`, labels, names, display names, and season type sections. |
| Get player splits | `athleteId` or `playerName`, optional `season`, optional `splitType`, optional `league` | Situational split tables such as home/away, opponent, win/loss, month, or other available splits | Resolve `athleteId` if needed; call common-v3 `/athletes/{id}/splits`; normalize `splitCategories`, labels, display names, descriptions, and categories. |
| Get player game stats | `athleteId` or `playerName`, plus `eventId`; optional `teamId`, `competitionId`, `competitorId`, `split` | Single-player game stat line: passing, rushing, receiving, defensive, kicking, turnovers, totals, and source stat names | Resolve `athleteId` if needed; if `competitionId` or `competitorId` is missing, call site-v2 `summary?event={eventId}`; read `header.competitions[].id` for `competitionId`; find the player's team in `boxscore.players[]` or roster data; use `boxscore.teams[].team.id` as `competitorId`; call core-v2 `/events/{event}/competitions/{competition}/competitors/{competitor}/roster/{athlete}/statistics/{split}`; normalize `splits.categories[].stats[]`. |
| Get player news | `athleteId` or `playerName`, optional `league` | Player-related articles/headlines and links | Resolve `athleteId` if needed; call site-v2 `/athletes/{id}/news`; optionally combine with Search v2 article results for the name. |
| Resolve team ID | `teamName`, optional `league` | Canonical `teamId`, abbreviation, display name, location, nickname | Call site-v2 `/teams`; match by display name, location, nickname, abbreviation, or slug; optionally use Search v2 for ambiguous names. |
| Get team profile | `teamId` or `teamName`, optional `season`, optional `league` | Team name, abbreviation, location, nickname, colors/logos where available, venue, links | Resolve `teamId` if needed; call site-v2 `/teams/{id}` for friendly detail; call core-v2 `/seasons/{season}/teams/{id}` when logos, venue refs, and core graph fields are needed; optionally call core-v3 `/teams/{id}` for v3 expansion shape. |
| Get team roster | `teamId` or `teamName`, optional `season`, optional `league` | Roster grouped by position with `athleteId`, name, jersey, position, links | Resolve `teamId` if needed; call site-v2 `/teams/{id}/roster`; parse athlete IDs directly from roster entries; optionally call common-v3 `/teams/{id}/roster` for position-group roster shape. |
| Get team depth chart | `teamId` or `teamName`, optional `season`, optional `league` | Starters and backups by position | Resolve `teamId` if needed; call site-v2 `/teams/{id}/depthcharts`; normalize positions, depth ranks, and athlete IDs. |
| Get team schedule | `teamId` or `teamName`, `season`, optional `league` | Full team schedule with event IDs, dates, opponents, home/away, game status, scores/results when available | Resolve `teamId` if needed; call site-v2 `/teams/{id}/schedule?season={season}`; normalize `events[]`, opponent team IDs, home/away, status, score, and links. |
| Get team next game | `teamId` or `teamName`, optional `date`, optional `season`, optional `league` | Next scheduled event with opponent, date/time, venue/broadcast where available | Resolve `teamId`; call team schedule for season; compare event dates/status against provided date or current date; select first future/non-final event; optionally call site-v2 summary or core-v2 competition for venue/broadcast enrichment. |
| Get team previous game | `teamId` or `teamName`, optional `date`, optional `season`, optional `league` | Most recent completed game with event ID, opponent, score, result | Resolve `teamId`; call team schedule for season; compare event dates/status against provided date or current date; select latest final event; optionally call site-v2 summary for boxscore summary. |
| Get team game stats | `teamId` or `teamName`, plus `eventId`; optional `competitionId`, `competitorId` | Team box score stats such as total yards, turnovers, first downs, penalties, possession, and source stat names | Resolve `teamId` if needed; if `competitionId`/`competitorId` missing, call site-v2 `summary?event={eventId}` and match `boxscore.teams[].team.id`; call core-v2 `/competitors/{competitor}/statistics`; normalize `splits.categories[].stats[]`. |
| Get team game leaders | `teamId` or `teamName`, plus `eventId`; optional `competitionId`, `competitorId` | Team leaders for passing, rushing, receiving, defense, kicking, or available leader categories | Resolve `teamId`; resolve `competitionId`/`competitorId` through site-v2 summary if needed; call core-v2 `/competitors/{competitor}/leaders`; normalize leader categories and athlete IDs. |
| Get scoreboard | `date` or `week`/`seasonType`/`season`, optional `league` | Games with event IDs, teams, scores, game state, period/clock where available, week and season metadata | Call site-v2 `/scoreboard` with `dates`, `week`, `seasontype`, `limit`, or other supported filters; normalize `events[]`, teams, competitions, scores, and status. |
| Get current week | Optional `league`, optional `season` | Current season type and week number | Call site-v2 `/scoreboard`; read top-level `season` and `week`; optionally use league calendar in scoreboard for available season types. |
| Resolve game/event | `eventId` or `teamName/teamId` plus date/week/opponent | `eventId`, `competitionId`, participating team IDs, competitor IDs | If `eventId` is provided, call site-v2 summary; otherwise resolve team ID, call team schedule or scoreboard, then match date/week/opponent; read `header.competitions[].id` for `competitionId`; read `boxscore.teams[].team.id` or competition competitors for `competitorId`. |
| Get game summary | `eventId` | Game header, teams, score, boxscore, leaders, injuries, drives, broadcasts, odds/pickcenter where available | Call site-v2 `/summary?event={eventId}`; normalize header, competitions, boxscore, scoring plays, leaders, drives, injuries, broadcasts, pickcenter/odds, and win probability. |
| Get box score | `eventId` | Team stats and player stat tables | Call site-v2 `/summary?event={eventId}` and use `boxscore`; optionally call CDN `/boxscore?xhr=1&gameId={eventId}` if ESPN page-package boxscore shape is needed; normalize teams and player stat tables. |
| Get play-by-play | `eventId`; optional `competitionId` | Ordered plays with quarter, clock, down/distance, yard line, team, text, scoring flag, play IDs | Resolve `competitionId` through site-v2 summary or core-v2 event if missing; call core-v2 `/events/{event}/competitions/{competition}/plays`; follow individual play IDs with `/plays/{play}` only when details are not already present; optionally use CDN `/playbyplay?xhr=1&gameId={eventId}` for display/page-package shape. |
| Get drives | `eventId`; optional `competitionId` | Drives with drive ID, team, start/end field position, result/description, time elapsed, plays when available | Resolve `competitionId` if missing; call core-v2 `/drives`; call `/drives/{drive}` for detail; optionally call `/drives/{drive}/plays` for play lists. |
| Get scoring plays | `eventId` | Scoring plays with quarter, clock, scoring team, text, score after play | Call site-v2 summary and read `scoringPlays`; optionally cross-link to core-v2 plays by play ID when available. |
| Get win probability | `eventId`; optional `competitionId` | Per-play home/away/tie win probability, associated play IDs, timestamps when available | Resolve `competitionId`; call core-v2 `/probabilities`; follow `/probabilities/{play}` for detail; read `play.$ref` if the SDK needs play text; optionally use site-v2 summary `winprobability` for display shape. |
| Get live situation | `eventId`; optional `competitionId` | Current down, distance, yard line, red zone, timeouts, possession context, last play | Resolve `competitionId`; call core-v2 `/situation`; follow `lastPlay.$ref` to core-v2 `/plays/{play}` when last play text/detail is requested. |
| Get game odds | `eventId`; optional `competitionId`, optional `provider` | Spread, over/under, moneyline or available odds fields, provider metadata | Resolve `competitionId`; call core-v2 `/odds`; optionally call core-v2 `/providers/{id}` for provider metadata; optionally use site-v2 summary `pickcenter`/`odds` for display package. |
| Get broadcasts | `eventId`; optional `competitionId` | TV/streaming broadcast entries with network, market, language/region where available | Resolve `competitionId`; call core-v2 `/broadcasts`; normalize media/station/type/market fields. |
| Get venue | `eventId` or `teamId/teamName`, optional `season`, optional `venueId` | Stadium name, city/state/country, indoor/grass, images | If `venueId` is provided, call core-v2 `/venues/{venueId}`; if `eventId` is provided, call core-v2 competition and follow `venue.$ref`; if team is provided, resolve team ID and call core-v2 season team or core-v3 team expansion to find venue ref. |
| Get standings | Optional `league`, optional `season` | Conference/division standings tree with team records and ranks where available | Call site API `/apis/v2/sports/football/{league}/standings`; do not use site-v2 `/standings` as a data source because it returned only `fullViewLink` in NFL docs. |
| Get league leaders | `category`, optional `season`, optional `limit`, optional `league` | Ranked players for passing yards, rushing yards, receiving yards, sacks, interceptions, or requested category | Call common-v3 `/statistics/byathlete` with supported query params; normalize pagination, categories, athlete rows, stat values, and glossary. |
| Get team statistical rankings | `category`, optional `season`, optional `limit`, optional `league` | Ranked teams for offense, defense, scoring, yards, or requested category | Call common-v3 `/statistics/byteam`; normalize team rows, categories, stat values, and glossary. |
| Get injuries | Optional `teamId/teamName`, optional `league` | Injured players with team, position, status, notes/details when available | Call site-v2 league `/injuries`; if a team is provided, resolve `teamId` and filter returned injuries client-side; do not rely on site-v2 team `/injuries` for NFL because it returned `{}` in the tested docs. |
| Get transactions | Optional `teamId/teamName`, optional date range/year, optional `league` | Transactions such as signings, releases, trades, waivers, with team/player info where available | Call site-v2 league `/transactions`; apply date/team filters client-side when necessary; do not rely on site-v2 team `/transactions` for NFL because it returned `{}` in the tested docs. |
| Get league news | Optional `league`, optional `limit` | League news articles/headlines and links | Call site-v2 `/news` for article package; optionally call Now news with `sport=football` for headline feed. |
| Search news/content | `query`, optional `type` | Matching articles, videos/clips, web links, IDs | Call Search v2 with `query`; use `results[].contents[].id` for non-player content IDs and links for web URLs; filter by result type when requested. |
| Get draft info | `season`, optional `team`, optional `league` | Draft rounds, picks/positions/status/broadcast data where available | Call site-v2 `/draft`; optionally filter by team or round client-side if the response shape includes enough fields. |
| Resolve IDs bundle | Any combination of `playerName`, `teamName`, `eventId`, `date`, `opponent`, `season`, `week` | Canonical `athleteId`, `teamId`, `eventId`, `competitionId`, `competitorId`, `uid`, `guid` where applicable | Use Search v2 for players; site-v2 teams for teams; site-v2 scoreboard/team schedule for event discovery; site-v2 summary for `competitionId` and competitor/team IDs; core-v2 competition if core refs are required. |

## Normalized ID Rules

Use these IDs as canonical SDK keys:

| Entity | Canonical SDK ID | Source |
| --- | --- | --- |
| Player | Numeric `athleteId` | Parse from Search v2 player `uid` after `~a:` or read directly from roster/athlete endpoints. |
| Team | Numeric `teamId` | Site-v2 teams, team schedule, summary boxscore teams, or core team refs. |
| Event/game | Numeric `eventId` | Site-v2 scoreboard, team schedule, summary, or core-v2 events. |
| Competition | Numeric `competitionId` | Site-v2 summary `header.competitions[].id` or core-v2 event `competitions[].$ref`. |
| Competitor | Numeric `competitorId` | Site-v2 summary `boxscore.teams[].team.id` or core-v2 competition `competitors[].$ref`. |
| Play | Numeric `playId` | Core-v2 plays, drives, situation `lastPlay.$ref`, or probabilities. |
| Drive | Numeric `driveId` | Core-v2 drives. |
| Venue | Numeric `venueId` | Core-v2 competition `venue.$ref`, team venue refs, or venues collection. |

Keep ESPN `uid` and `guid` as metadata. Do not use Search v2 player
`contents[].id` as the athlete path ID; live tests showed that field is a GUID
and returned `400` when used in athlete URLs.
